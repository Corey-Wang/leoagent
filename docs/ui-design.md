# LeoAgent UI 设计规范

这份规范用于 Android 手机端，落实用户依据 [Huashu Design](https://github.com/alchaincyf/huashu-design) 本轮选定的 A「静默协作」，并保留既有原生交互与可访问性原则。目标是让用户在小屏幕上快速判断电脑、Agent、任务和审批状态，再完成下一步操作。

## 1. 产品气质

LeoAgent 是“远程控制台”，不是普通聊天应用。界面需要安静、清晰、可恢复：

- **状态优先**：连接、任务、审批、未知结果必须在首屏有明确状态。
- **动作单一**：每个区域只保留一个主要动作；危险动作使用明确的确认文案。
- **证据可回看**：任务回执、事件序号、审批结果和错误原因在消息与任务卡片中可追溯。
- **低打扰**：运行中的任务显示进度，后台提醒只告诉用户“需要处理什么”，不强迫用户一直停留在对话页。

## 2. 视觉 Token

| Token | 规则 |
|---|---|
| 页面背景 | 浅色 `#FFFFFF`，深色 `#141820`；平面背景，不使用顶部柔光 |
| 卡片 | 工具使用 `surface` 与 `border` 细描边，圆角 12dp；列表用细分隔线，Agent 正文直接阅读 |
| 主色 | `primary` 用于链接和选中态；`primaryFill` 为白字按钮固定靛蓝 `#414D9D`；浅色正文 `#232A38`、次级文字 `#626B7A`，深色链接使用亮靛蓝 |
| 危险色 | `strong` 只用于停止、拒绝、未知风险和严重错误；错误同时显示文字，不只依赖颜色 |
| 成功色 | `down` 只用于成功状态；状态必须同时有文字或图标 |
| 间距 | 4dp 基线，常用 8/12/16/24/32dp；卡片内部至少 16dp |
| 触控 | 按钮、图标操作、文件入口最小 48dp；按钮组保留 8dp 间隔 |
| 圆角 | 按钮与工具面板 12dp，用户消息和组合输入区 16dp，状态标签可使用胶囊 |

## 3. 字体与文案

- 内容页大标题使用 28–32sp，对话顶栏标题 16sp；区块标题 13sp；正文 16–17sp；说明 12–13sp。
- 标题和状态短句避免孤行；长标题最多两行，列表内容允许省略并保留完整内容在详情页。
- 加载文案使用“加载中…”、“连接中…”、“保存中…”；不用三个英文句点。
- 错误文案必须包含下一步，例如“设备授权已失效，请重新配对”，不能只显示 HTTP 状态码。
- 状态使用主动语态：“任务已接受”“等待你的审批”“结果未知，点击核对”。
- 数量、时间、版本和任务 ID 使用等宽数字或 `tabular-nums` 风格，便于比较。

## 4. 可访问性与输入

- 所有图标按钮必须有中文 `contentDescription`；装饰性图标隐藏在辅助功能树中。
- 所有输入框必须有可关联的可见标签，并设置 `labelFor`；凭据输入使用密码类型，不阻止粘贴。
- 所有可点击行、按钮和图标都要可获得焦点，键盘/辅助开关操作时显示主色焦点描边。
- 普通操作保留 `isFocusable = true`，使用 `isFocusableInTouchMode = false`；输入框可以获取触摸焦点。不能让非编辑按钮的第一次触摸只聚焦而不执行。验收必须发送真实触摸事件，`performClick()` 不覆盖这种回归。
- 点击区域不小于 48dp；不要把操作只放在小箭头或滑动手势上。
- Toast 只用于短反馈；重要错误、审批和未知结果使用可见卡片或对话框。
- 文本、图标和状态颜色在浅色/深色主题中都要保持足够对比；颜色不是唯一状态信号。

## 5. 页面模式

### Agent 对话

1. 顶栏：对话列表、会话标题与模型、桌面画面、差异和更多操作。项目与审批方式独立一行，可点击切换项目。
2. 状态条：连接问题和任务状态分开显示。点击“结果未知”进入核对，不自动重发。
3. 消息区：用户使用浅灰消息面，Agent 使用无框正文；思考次级显示，工具详情可折叠。审批固定在输入区上方的浅靛灰面板中，并提供对应深色背景。
4. 输入区：文字独占上行；下行包含图片、当前 Agent/模型、语音、发送/停止。发送和停止保持同一位置。
5. 审批：直接展示请求摘要与详情前两行，拒绝在左、允许一次在右。拒绝需再次确认；完整请求面板保留全部 Agent 授权选项。提交后收起并显示等待电脑回执，失效请求随服务端状态清除。
6. 新消息按钮：离开底部时显示“回到最新”，未读数量单独显示。

### 导航与系统通知

- 对话占据主界面，不使用底部导航或独立消息中心。
- 左侧抽屉突出当前项目，保留会话搜索；「新对话」与「设置」固定在底部；设置打开完整页面。
- 设置顶栏提供「返回对话」，系统返回键也回到原会话，未发送内容保留；旧消息 Tab 的偏好不再参与启动。
- 任务完成、审批与提问通过系统通知提醒，点击打开对应会话；前台对话不显示重复提醒。
- 消息中心的未读角标、历史列表、已读操作与定时刷新均移除。

### 设置与配对

- 配对流程分为：填写/扫描链接 → 显示验证码 → 电脑确认 → 保存设备凭据。
- URL 和设备凭据使用明确标签；保存按钮保持可见，失败时保留用户输入。
- 连接状态包含电脑版本、任务恢复能力和下一步操作。
- 危险操作（撤销设备、清除等待记录、停止任务）必须确认，并说明已产生的文件或 Agent 副作用不会被回滚。

### 文件审阅

- 全屏「文件改动」使用真实项目 diff，显示项目、分支和 Git 统计，按文件展开或收起。
- 代码保留水平滚动与增删颜色；较大改动明确提示只展示前 6000 行。
- 文案明确为项目当前未提交改动，不声称全部属于当前任务。非 Git、空改动与读取失败均有说明。

## 6. 状态和动效

- 任务状态至少覆盖：准备中、执行中、等待审批、等待回答、停止中、核对中、成功、失败、已停止、未知。
- 连接断开、服务重启或回执不可用时，显示“结果未知”而不是“失败”，并提供核对入口。
- 尊重系统“移除动画”设置；关闭动画时保留静态加载状态，不闪烁、不依赖颜色变化。
- 动效只使用透明度和位移，时间短且可被用户操作打断；不能阻塞发送、停止或审批。

## 7. 组件验收清单

- [ ] 图标按钮有 `contentDescription`，列表行和主要按钮可获得焦点。
- [ ] 输入框有标签、正确输入类型和 48dp 以上触控高度。
- [ ] 加载、错误、空状态和未知状态都有可读文字与下一步动作。
- [ ] 浅色和深色主题均能读清正文、状态和禁用态。
- [ ] 长项目名、长任务标题、长错误信息不会把按钮挤出屏幕。
- [ ] 系统关闭动画后，页面仍能完成连接、发送、审批和恢复。
- [ ] 横竖屏、刘海/导航栏和键盘弹出时，底部输入区与主要操作仍可见。

## 8. 当前实现对应关系

- `android/.../UI.kt`：颜色、间距、圆角、焦点描边、按钮和分组组件。
- `android/.../CodexPane.kt`：对话顶栏、任务状态、输入区、审批和未知回执。
- `android/.../MainActivity.kt`：主对话与设置切换、首次配置引导、通知跳转和连接状态。
- `android/.../SettingsActivity.kt`：配对、凭据标签、连接测试和升级入口。

本次改版不修改服务端协议。本轮原生验收与截图见 `docs/redesign-v2/implementation.md`；上一轮证据保留在 `docs/redesign/`。

# 当前桌面会话续聊修复

状态：用户明确回复“部署”后已替换正式服务并重启，线上本机接口与原桌面会话连接验证通过。手机继续使用 0.1.7，无需更新 APK。部署证据见 `deployment.json`，构建前的隔离验证记录保留在 `verification.json`。

## 原因与实际影响

Android 0.1.7 已统一使用持久任务入口，电脑端 worker 却只接受带 ACP RPC 的执行句柄。附着桌面会话后该句柄没有 ACP RPC，worker 因此接受任务后失败。实际报错记录的 `dispatch_started=0`：这一条失败消息没有派发到 Agent。

## 修复范围

- 原会话通过桌面 IPC 发送文本/图片，持久任务继续保留项目互斥、操作 ID、快照与回执。
- 使用本轮用户消息的唯一标识关联对应回合，等明确的完成/中断/失败；不以启动应答、旧回合或临时空闲判断完成。
- 补丁无法完整应用时重新同步，不将部分状态作为完成证据；失效句柄停止接收事件。
- 桌面执行上一轮或基线未同步时明确不发送。派发后超时、断线、服务重启保留未知，不自动转 ACP。
- 审批发送未确认时保留未知回执，后续快照不重新生成可重复审批卡片；异步回答发送不确定时不另起回合。
- Android 接口与版本、数据库格式均不变。手机现有 0.1.7 可直接使用修复后的电脑端。

## 证据范围

只读核对了当前 Codex 桌面状态的结构，确认回合 `turnId/status/items` 与用户项 `clientId`；没有向真实桌面会话发消息。隔离测试使用真实 HTTP 服务和真实持久任务 worker，桌面 IPC 由临时 socket fixture 提供。原 ACP 回归仍使用受控 ACP 子进程。具体命令、结果和候选文件摘要见 `verification.json`。

隔离测试覆盖原桌面会话续聊、图片、重复提交、结束事件先于启动回执、结束事实优先于失败应答、明确失败、无关回合/临时空闲/部分补丁隔离、桌面忙碌、审批及输入回执重放、审批结果未知后不重新出卡、异步补充未知后不重发、停止、真实 60 秒发送超时、断线、重启不重发且不启动 ACP。

# Android 发送闪动与流式显示修复

用户明确回复「发布」后，0.1.8（9）已发布到现有「检查更新」通道，版本接口、完整下载和下载包签名核验通过，详见 [发布记录](publication.json)。本轮未安装或操作物理手机、重启生产服务、发送真实模型测试任务、提交或推送 Git。

## 原因与修改

- `CodexPane.send()` 收到回执后重启流，`startStream()` 无条件清空聊天区并重绘快照；打开会话也重复读取快照。现在发送复用活动连接，打开会话复用刚读取的快照；同一 data_epoch 重连保留视图，从原 lastSeq 补事件。数据代数改变、游标失效才重建。快照的全局 cursor 不会提前覆盖尚未显示的事件游标。
- 执行状态原先在滚动区上方，显隐会改变聊天视口高度。现在与回复同处滚动容器，发送立即显示状态，滚动计算包含状态行；移除重复的呼吸点。
- 移除额外的逐字追赶，按 32ms 合并渲染当前已收到全文。终态事件先同步末尾文字，再隐藏执行状态。较晚到达的提交回执保留 SSE 已确认的 running/终态。
- 请求头统一为既有 Android User-Agent，只读对照未证明它是慢的原因。

## 真实慢的边界

只读生产记录显示最近两轮首条 msg 分别约 37 秒、41 秒才产生，属于电脑端/模型首段输出前的等待；当前补丁改善手机反馈、刷新和收到文字后的显示，不承诺缩短这部分时间。保留原模型及 high 推理强度。事件总线现有批量刷新约 40ms。

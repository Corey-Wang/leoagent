# 1.0 正式版验收

目标：新用户能完成连接、选择项目、提交任务、处理审批/提问、离开对话接收提醒，并在断线或重启后核对结果。当前是本地候选开发阶段，尚未宣布 1.0 就绪；用户要求暂不发版。常驻服务、更新源和旧配对认证保持不变。

## 本轮落地

| 用户行为 | 实际行为与证据 |
|---|---|
| 空消息库中完成第一个任务 | 显式区分初始化与游标零；真实 HTTP 长轮询收到第一条消息 |
| 短时间产生大量消息 | 增量按序号升序、历史按降序分页，SQL 有界；235 条突发补取无缺口 |
| 任务完成或需要交互时崩溃 | 通知与任务终态/交互事实在同一 SQLite 事务提交；事务回滚不留下通知，重复交互不重复提醒 |
| 结果失败、停止或未知 | 分别显示错误、停止和待核对消息；未知结果不会显示成成功，不自动重跑 |
| 离开对话/回到前台 | 模拟器实际 NotificationManager 验证后台有提醒，正在显示的对话免打扰；隐藏对话不占用前台标记 |
| 点击系统通知 | 回到关联对话；通知附带服务器标识，切换服务器后不会打开错误电脑上的同名会话 |
| 关闭通知权限 | 不强迫首屏授权；设置/消息页显示入口。拒绝权限后仍补取游标、保留消息，模拟器验证通过 |
| 打开消息页 | 展示近 7 天记录与未读数，不自动清空未读；支持明确标记全部已读、历史分页、失败重试 |
| 进程重启/切换服务器/数据恢复 | 按服务器保存已读与投递游标，恢复数据代数变化时重置；隔离包实际进程重启验证状态保留 |
| 首次使用 | 未连接时引导配对，未选项目时引导选择目录；空凭据/非法地址直接给出字段提示 |
| 查看连接设置 | 显示电脑连接与任务恢复能力；异步结果绑定原连接，切换连接不更新到错误页面 |
| 从二进制包安装 | 随包提供安装脚本、launchd 模板、预编译程序和 START-HERE；无需 Cargo；支持只准备文件的 `--no-start` |

后台提醒仍是前台服务长轮询，不承诺云推送：手机强行停止应用、系统杀进程或长时间限制后台时，重新打开消息页补查。消息保留 7 天；通知本身不能证明审批仍有效，当前快照才是依据。

## 可复现检查

均使用临时 HOME、项目和数据库，以及受控 ACP fixture；不调用个人 Agent、不操作正式 App。

```bash
cargo test --locked --manifest-path server/Cargo.toml
cargo build --locked --manifest-path server/Cargo.toml
python3 tests/notifications.py
LEOAGENT_CONTRACTS=1 /path/to/test-venv/bin/python tests/integration.py
cd android
./gradlew --offline -Pleoagent.verification :app:assembleDebug :app:assembleDebugAndroidTest :app:lintDebug
cd ..
python3 tests/android_integration.py
```

Rust 14 个测试通过，包括通知与事实的事务回滚、重复交互和未知终态不被成功覆盖。真实 HTTP/ACP 回归和 Android 隔离验收均通过。模拟器测试还检查 SSE 真实流过代理，避免缓冲整个响应掩盖实时问题。截图在 `android/app/build/reports/notifications/`，重新构建/清理可能删除。

二进制发行包已用 `python3 tests/install_package.py /absolute/path/to/archive.tar.gz` 核验全新暂存安装、升级保留旧配置与 Token、前一份程序、带空格/`&` 路径、指定配置参数及实际暂存程序 HTTP 启动。该检查不注册 launchd；真实登录会话的自启动/重启/回滚不能据此标为通过。

## 宣布正式版前仍需补证据

| 门槛 | 当前边界 / 下一步 |
|---|---|
| 手机系统行为 | 模拟器后台、权限与进程重启已有证据；物理手机锁屏、Wi-Fi/蜂窝切换和厂商电池限制需实测 |
| 真实安装与升级回滚 | 临时 HOME 可验证文件和配置；正式用户登录会话的 launchd 自启动、升级与匹配备份回滚需独立环境验收 |
| 支持矩阵 | 已有一次 macOS + Codex ACP 最小真实任务；Linux、其他 Agent 和完整实验桌面同步需各自验证，不扩大支持承诺 |
| 公开仓库审查 | 当前全部 2 个历史提交、198 个 blob 的常见凭据模式扫描未命中；macOS Rust 依赖元数据 119 包均有许可证表达式。仍需人工复核敏感信息、Android/捆绑库与随包许可文本，并配置可实际联系的安全报告渠道 |
| CI 与发行产物 | 工作流和本地签名构建已具备；远端 CI、最终版本号、签名/校验和、发行内容需针对最终候选核对 |
| 发布操作 | 当前未获新发布授权，按用户决定保持未发布；候选开发不改变现有更新源或停用旧配对码 |

后续迭代优先完成以上证据缺口，再决定正式版本号。不能以编译通过、mock 成功或已有签名包代替这些验收。

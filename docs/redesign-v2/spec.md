# LeoAgent 第二轮设计探索

2026-10-26。用户本轮请求原话：「用 huashu-design重新设计LeoAgent」。以下保留三方向探索阶段规格。本目录独立于既有 `docs/redesign/`；用户随后选择 A「静默协作」，已在现有 Android 修改上增量落实，原生结果见 [implementation.md](implementation.md)。

## 共同事实与边界

依据仓库 README、`docs/ui-design.md`、`UI.kt`、`CodexPane.kt`、`MainActivity.kt`。LeoAgent 是手机操控自己电脑上编程 Agent 的 Android 原生应用。当前导航以对话为中心，抽屉进入项目/会话和设置，没有底部导航或独立消息中心。第二轮必须沿用这条最新结构，不能复制旧原型的三个底部 Tab。

本轮改善目标：手机首屏读清当前项目、电脑连接、任务状态与审批内容；用拇指完成批准或拒绝；保留长对话阅读与后续输入；容易回到正确项目续聊。连接断开不等于任务停止，结果未知不得自动重发。不能通过想象增加多电脑管理、云服务、任务百分比、费用、速度或成功率。

四个主界面：①正在等待批准的对话；②项目与会话（从抽屉可达）；③本轮文件改动；④连接与设置。四台 Android 设备，每台都独立可操作且可导航到其余屏。不要底栏，设置有返回对话。每台保留键盘友好 focus。演示文字输入和审批只改变本机原型状态，绝不执行命令、访问真实服务或保存凭据。

## 三版必须统一的真实内容（样例）

- 项目 `leoagent`；当前会话「修复登录校验」；电脑 `MacBook Pro`；Agent `Codex`。这些是明确标注的界面样例，不是实时状态。
- 用户：「修复登录表单的输入校验，并运行测试。」
- Agent：「已补齐邮箱格式和空密码校验，也加上了对应的测试。运行测试前，需要你批准下面的命令。」
- 文件 `LoginForm.kt`（+18 −4）、`LoginFormTest.kt`（+10）；文件与差异数字全为样例。
- 待执行命令 `./gradlew testDebugUnitTest`；工作目录 `leoagent/android`。允许一次 / 拒绝。这是尚未执行的演示审批，不暗示测试已成功。
- 执行记录为「阅读登录逻辑」「修改 2 个文件」「等待批准运行测试」。没有伪造完成后的测试结果。
- 批准后文案：「已允许本次操作（演示）」；后续「等待电脑回执」。拒绝后「已拒绝本次操作（演示）」；文件改动仍然保留。
- 其他会话：「完善深色主题」（已完成）、「检查连接恢复」（结果待核对）。选择后切换真实标题与状态，核对状态提供查看已有改动入口。
- 设置：样例电脑与连接、编辑地址（`https://leoagent.example.com`）、连接测试演示、配对流程演示、通知开关、外观。原型不显示版本号、不上传日志、不制造真的网络反馈。
- 配对：先填写邀请链接，再展示明确标为样例的验证码，让用户在电脑核对。显示「等待电脑确认」，不可假装真的配对成功。
- 差异样例：`+ if (!isValidEmail(email)) return EmailError`、`+ if (password.isBlank()) return PasswordError`、测试名称 `rejectsInvalidEmail()` / `rejectsEmptyPassword()`。

## 形态与可访问性

- 三版统一 Android 内容视口 390 × 844，使用 skill `assets/android_frame.jsx` 的外壳参数（10px 外边、44px 外圆角、36px 屏圆角、32px 状态栏、14px 打孔、24px 手势区）。允许转写成离线 HTML/CSS。
- 每版一份自包含 HTML，所有 logo 内嵌 data URL，无 CDN 或外部请求。原生图标沿用仓库 Material Symbols 路径。
- 每版有一张具有主次构图的展示板，至少四屏；每台实际显示宽度 ≥300px，不用四台等距一字排开。版与版展示板骨架也应不同。桌面优先以 1440px 宽观看，可向下滚动；移动 390/375/320px 退为单台可切屏，不能横向溢出。
- 正文 16px，次要正文至少14px，标签至少12px；正文对比度≥4.5；主要操作触控48px，图标按钮48px；可访问名称、可见焦点；Esc 关闭弹层，弹层焦点管理；减少动画设置。
- 审批摘要、命令、主要批准/拒绝按钮在390×844首屏可见；批准/拒绝不能触发其他设备状态；不能丢未发送草稿；使用 textContent 或转义用户输入。
- 无不相关照片、假图表、装饰性编号、Emoji、品牌 logo 墙。内容主角是任务、文件改动与请求；三版不能仅换颜色。

## form 五问

| 屏 | 角色/距离 | 温度与容量 | 由内容决定的结构 |
|---|---|---|---|
| 对话 | 手机近距核心操作 | 冷静；任务、回复、当前审批 | 一眼同时看到命令、项目、批准动作 |
| 会话 | 回到工作 | 有秩序；三个示例会话 | 项目先于会话，等待审批与待核对可辨 |
| 改动 | 做决定的证据 | 精确；两文件、数行差异 | 文件名和新增/删除共同表达，不只靠颜色 |
| 设置 | 可信连接 | 稳定；当前电脑、配对、偏好 | 连接与任务分开，凭据不默认明文 |

探索阶段假设：沿用名称、原始狮子 Logo、Kotlin Views 产品形态；没有收到额外风格偏好时，由当前任务场景推导三个方向。HTML 是方向选择阶段产物；选定后的原生修改与验证单独记录。
